Open this plan as one or more tickets in the form of comprehensive git issue(s) to hand off for implementation. Determine the optimal number of issues to be created; the plan should not be split awkwardly or unnecessarily but the scope of each ticket should be manageable. Tickets will be implemented in order, so order dependency / blocking is acceptable. The app is currently in the testing/development phase with no active users, so temporary breakage or downtime between issues is also acceptable. 

 Make sure that every key design decision made during the grilling/planning is explicitly stated in the issue(s). Each issue should be a fully fleshed out implementation plan.
